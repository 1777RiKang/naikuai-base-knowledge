# 审核指南

## 必查项

1. 术语是否真的是玩家常用说法，而不是一次性玩梗。
2. 释义是否区分了「物品本身」和「服务/档位」。
3. 别名是否与现有词条冲突（CI 会报，但要看语义是否真冲突）。
4. 组合词是否拆得开、成分是否有独立条目。
5. 来源是否标对：玩家标注 ≠ nkwiki。
6. 证据是否脱敏，是否包含价格。
7. `canonical` 是否可被新玩家理解。
8. 贡献名是否由本人自选公开，是否存在重复知识点刷分；改名配置的 ID 是否与申请者一致。
9. 所有外部 PR 由维护者批准；维护者自提 PR 可免他人审批，但不能跳过 CI。

## 常见问题

- **同物多写法**：合并为一个词条 + 别名，不要建多条。
- **同词多义**：使用 `senses` 记录不同语境，回答时按语境选。
- **版本差异**：在 `senses[].notes` 写清适用版本，不删旧义项。
- **服务档位**：`kind: service`，`definition` 写明服务内容而不是道具属性。

## 处理冲突

1. 评论里贴证据，不引用私聊。
2. 无法说服对方 → `status: disputed`，维护者发起 Discussion 投票。
3. 未解决的争议可以按 disputed 收录，明确记录依据，AI 默认不引用。
4. 紧急错误也通过 PR 修正，先完成 CI；维护者可自行合并自己的 PR。

## 合并后

- 确认 CI 绿、构建产物可下载。
- 打 tag 前跑一次影子测试（固定问句集）。
- 部署只替换 sqlite，不重启业务进程。
